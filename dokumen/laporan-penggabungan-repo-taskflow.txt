1. RUANG LINGKUP DAN PERMINTAAN

Laporan ini mendokumentasikan pekerjaan pada permintaan sebelumnya: mengecek apakah repository GitHub memiliki perubahan baru dan menggabungkannya dengan progress yang sudah ada di komputer pengguna. Laporan juga mencatat pembuatan file dokumentasi ini pada permintaan saat ini.

6. PERUBAHAN BACKEND PHP

api/columns.php
- Endpoint kolom menggunakan bootstrap, session, dan koneksi database yang sama dengan sistem login.
- Setiap permintaan memerlukan pengguna yang sudah login dan merupakan anggota workspace.
- Daftar, pembuatan, dan penghapusan kolom menggunakan workspace_id.
- Nama, deskripsi, dan warna kolom divalidasi.
- Nama kolom yang menghasilkan ID sama dalam satu workspace mendapat akhiran unik.
- ID kolom yang sama diperbolehkan pada workspace berbeda.
- Kolom utama todo, in_progress, dan done tidak dapat dihapus.
- Penghapusan kolom tambahan memindahkan task di dalamnya ke todo hanya pada workspace yang sama.
- Perubahan kolom memakai transaksi dan penguncian baris workspace untuk mengatur perubahan task/kolom yang berlangsung bersamaan.

api/lib/columns.php
- Menyediakan fungsi pengisian tiga kolom utama untuk setiap workspace.
- Menyediakan validasi bahwa status task benar-benar merupakan kolom pada workspace tersebut.

api/tasks.php
- Validasi status tidak lagi terbatas pada tiga status tetap.
- Task dapat dibuat atau dipindahkan ke kolom tambahan yang ada pada workspace aktif.
- Status dari workspace lain atau status yang tidak ada ditolak.
- Pembatasan task berdasarkan workspace dan pemeriksaan anggota tetap berlaku.
- Operasi perubahan task disesuaikan dengan transaksi dan penguncian workspace.

api/workspaces.php
- Pembuatan workspace otomatis membuat tiga kolom utama dalam transaksi yang sama.

api/bootstrap.php
- Memuat helper kolom agar endpoint dapat menggunakan fungsi bersama.

Endpoint autentikasi dan pengaturan workspace yang sudah ada tetap terintegrasi dengan sistem hasil penggabungan.

7. PERUBAHAN DATABASE DAN MIGRASI

database/schema.sql
- Mempertahankan tabel users, workspaces, workspace_members, dan tasks.
- Menambahkan struktur columns dengan primary key gabungan workspace_id dan id.
- Menambahkan relasi kolom ke workspace.
- Status task menggunakan VARCHAR(50) untuk menampung kolom tambahan.
- Menambahkan indeks gabungan workspace_id dan status untuk pencarian task pada workspace.

database/migrate.php
- Dapat dijalankan pada database lama tanpa menghapus akun atau task.
- Melengkapi struktur workspace dan pembuat task jika belum ada.
- Menghubungkan task lama ke workspace awal TaskFlow Hackathon.
- Mengubah status ENUM menjadi VARCHAR jika diperlukan.
- Jika tabel columns versi lama masih global, kolom tersebut dipindahkan ke workspace awal.
- Menyesuaikan primary key kolom menjadi gabungan workspace_id dan id.
- Membuat kolom utama pada semua workspace yang sudah ada.
- Membuat kolom pengganti jika terdapat status task lama yang belum mempunyai kolom, agar task tetap terlihat.
- Mempertahankan label dan warna kolom lama.
- Memeriksa struktur sebelum menambahkan bagian yang sudah ada, sehingga migrasi dapat dijalankan ulang.

database/seed.sql
- Mempertahankan data contoh yang sesuai dengan workspace awal.
- Data contoh tidak digunakan untuk menimpa data pengguna pada proses penggabungan.

Migrasi diterapkan pada database taskflow setelah pengujian pada database sementara berhasil.

Hasil pemeriksaan database utama:
Sebelum migrasi: 2 akun, 1 workspace, 8 task.
Setelah migrasi: 2 akun, 1 workspace, 8 task, 3 kolom utama.

Jumlah akun, workspace, dan task tetap sama. Pengujian tidak membuat akun percobaan pada database utama.

9. PENGUJIAN DAN TEMUAN YANG DIPERBAIKI

Pengujian menggunakan database sementara dengan awalan taskflow_test_. Database sementara dibuat khusus untuk pengujian dan dibersihkan setelah selesai. Server pengujian menggunakan port berbeda dari aplikasi pengguna.

Sembilan skenario browser/API berhasil pada pengujian akhir:

2. Membuat workspace, tambah/pindah/drag/hapus task, filter, dan pemisahan task antar workspace.
3. Bergabung melalui kode, penolakan kode salah, dan kolaborasi task sebagai member.
4. Owner mengubah workspace, mengganti kode undangan, dan mengeluarkan anggota.
5. API menolak akses tanpa hak serta manipulasi ID task antar workspace.
6. Tampilan layar kecil, validasi form, dan navigasi keyboard dialog.
7. Form mempertahankan input saat penyimpanan gagal dan kembali ke login saat session berakhir.
8. Kolom custom, pilihan warna, persistensi setelah reload, task pada status tambahan, dan penghapusan kolom yang terisolasi per workspace.
9. Hak akses API kolom, validasi warna/status, perlindungan kolom utama, ID kolom duplikat, serta kegagalan penyimpanan kolom.

10. KRITERIA SELESAI

Pekerjaan penggabungan dianggap selesai jika:
- Perubahan repository terbaru berhasil diambil.
- Progress login dan multi-workspace lokal tetap berfungsi.
- Kolom custom dapat ditambah, ditampilkan, disimpan, dan dihapus.
- Warna dan status kolom tetap ada setelah halaman dimuat ulang.
- Task dapat dipindahkan ke kolom tambahan melalui pilihan status dan drag-and-drop.
- Kolom serta task tidak tercampur antar workspace.
- Penghapusan kolom memindahkan task hanya pada workspace yang bersangkutan.
- Kesalahan API tidak menghasilkan data palsu atau keberhasilan penyimpanan palsu.
- Akun, workspace, dan task lama tetap ada setelah migrasi.
- Konflik Git selesai, aplikasi berhasil dibangun, dan pengujian terkait berhasil.
- Backup progress dan database tersedia.
