6. PERUBAHAN BACKEND PHP

api/columns.php
- Endpoint kolom menggunakan bootstrap, session, dan koneksi database yang sama dengan sistem login.
- Setiap permintaan memerlukan pengguna yang sudah login dan merupakan anggota workspace.
- Daftar, pembuatan, dan penghapusan kolom menggunakan workspace_id.
- Nama, deskripsi, dan warna kolom divalidasi.
- Nama kolom yang menghasilkan ID sama dalam satu workspace mendapat akhiran unik.
- ID kolom yang sama diperbolehkan pada workspace berbeda.
- Kolom utama todo, in_progress, dan done tidak dapat dihapus.
- Penghapusan kolom tambahan memindahkan task di dalamnya ke todo hanya pada workspace yang sama.
- Perubahan kolom memakai transaksi dan penguncian baris workspace untuk mengatur perubahan task/kolom yang berlangsung bersamaan.

api/lib/columns.php
- Menyediakan fungsi pengisian tiga kolom utama untuk setiap workspace.
- Menyediakan validasi bahwa status task benar-benar merupakan kolom pada workspace tersebut.

api/tasks.php
- Validasi status tidak lagi terbatas pada tiga status tetap.
- Task dapat dibuat atau dipindahkan ke kolom tambahan yang ada pada workspace aktif.
- Status dari workspace lain atau status yang tidak ada ditolak.
- Pembatasan task berdasarkan workspace dan pemeriksaan anggota tetap berlaku.
- Operasi perubahan task disesuaikan dengan transaksi dan penguncian workspace.

api/workspaces.php
- Pembuatan workspace otomatis membuat tiga kolom utama dalam transaksi yang sama.

api/bootstrap.php
- Memuat helper kolom agar endpoint dapat menggunakan fungsi bersama.

Endpoint autentikasi dan pengaturan workspace yang sudah ada tetap terintegrasi dengan sistem hasil penggabungan.

14. FITUR DEADLINE TASK

Permintaan dan tujuan:
Pengguna menyetujui penambahan deadline sederhana agar tim dapat menentukan prioritas dan mengetahui task yang terlambat. Deadline berupa tanggal tanpa jam dan tidak wajib diisi.

Pekerjaan yang dilakukan:
- Menambahkan deadline DATE NULL pada tabel tasks melalui schema dan migrasi.
- Membuat migrasi memeriksa keberadaan kolom sebelum menambahkannya, sehingga aman dijalankan ulang.
- Memberi task lama deadline kosong tanpa mengubah data task lainnya.
- Memperluas POST/PATCH task untuk menerima deadline YYYY-MM-DD atau null.
- Memvalidasi format tanggal, batas tahun yang didukung database, dan keabsahan tanggal kalender, termasuk tahun kabisat.
- PATCH deadline tidak mengubah status jika status tidak dikirim.
- Menambahkan input tanggal opsional pada form tambah task.
- Menampilkan tanggal dan penanda deadline pada kartu.
- Menambahkan editor tanggal langsung di kartu dengan tombol simpan, hapus, dan batal.
- Mempertahankan tanggal yang tersimpan ketika API gagal dan mempertahankan input editor agar pengguna bisa mencoba kembali.
- Menghitung hari menggunakan Asia/Jakarta (WIB), bukan selisih jam atau zona waktu browser.
- Memperbarui waktu acuan board setiap menit agar penanda tanggal ikut berubah selama halaman terbuka.

Aturan penanda:
- Hari ini: deadline sama dengan tanggal hari ini di WIB.
- Segera: deadline satu atau dua hari setelah hari ini.
- Terlambat: deadline sudah lewat dan task belum berada di kolom Done.
- Deadline: tanggal lebih dari dua hari ke depan.
- Selesai: task berada di kolom Done, termasuk jika tanggal deadline sudah lewat.
- Task tanpa deadline tidak diberi penanda waktu; kartu menyediakan tombol Tambah deadline.

File yang dibuat atau diubah:
- src/utils/deadline.js: fungsi perhitungan dan format penanda.
- database/schema.sql dan database/migrate.php: kolom deadline serta migrasi.
- api/tasks.php dan src/api/tasks.js: penyimpanan dan perubahan deadline.
- src/components/AddTaskModal.jsx: input deadline saat membuat task.
- src/components/TaskCard.jsx: badge tanggal serta editor inline.
- src/components/WorkspaceBoard.jsx: perubahan state task dan waktu acuan.
- src/components/KanbanBoard.jsx dan KanbanColumn.jsx: penerusan data/callback.
- tests/migration.php dan tests/workspaces.spec.js: pengujian migrasi, tanggal, dan alur pengguna.
- README.md: cara menggunakan fitur dan menjalankan migrasi.

16. FITUR EDIT TASK

Permintaan dan tujuan:
Pengguna meminta fitur untuk mengedit task. Tujuannya memungkinkan owner dan member memperbaiki isi pekerjaan yang sudah ada tanpa menghapus lalu membuat ulang task.

Perilaku yang dibuat:
- Ikon pensil pada setiap kartu membuka form Edit task.
- Form menampilkan judul, deskripsi, status, dan deadline task yang sudah tersimpan.
- Status dapat dipilih dari kolom workspace aktif, termasuk kolom custom.
- Judul wajib berisi teks; deskripsi dan deadline boleh dikosongkan.
- Simpan perubahan mengirim data ke API dan memperbarui kartu dari hasil server.
- Jika status berubah, kartu berpindah ke kolom yang dipilih.
- Pencarian dan filter dibersihkan setelah penyimpanan berhasil agar kartu hasil edit tetap terlihat.
