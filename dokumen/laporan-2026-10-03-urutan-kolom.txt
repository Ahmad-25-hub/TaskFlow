1. PERMINTAAN DAN TUJUAN

Pengguna meminta agar posisi tahapan baru dapat diubah, dengan contoh kolom
Masalah yang ingin ditempatkan di antara In Progress dan Done. Pengguna juga
meminta file .txt yang menjelaskan pekerjaan, tujuan, dan kriteria selesai,
serta pembuatan folder dokumen jika belum tersedia. Dalam permintaan lanjutan,
pengguna memilih drag-and-drop seperti Trello untuk menggantikan tombol panah
dan meminta laporan ini diperbarui sesuai implementasi terbaru.

Istilah "task" dalam permintaan ditafsirkan sebagai kolom/tahapan papan,
berdasarkan contoh tersebut dan pembicaraan sebelumnya mengenai tiga kolom
utama. Fitur yang dibuat adalah pengaturan urutan kolom. Tujuannya agar
pengguna dapat menyesuaikan susunan tahapan dengan alur kerjanya.

2. KONDISI AWAL YANG DIPERIKSA

- Aplikasi menggunakan React dan Vite untuk frontend.
- Data task dan kolom disimpan melalui API PHP ke MySQL/MariaDB.
- API kolom sudah mengembalikan data berdasarkan field sort_order.
- Kolom tambahan selalu ditambahkan di akhir papan.
- Belum ada kontrol frontend maupun endpoint untuk mengubah urutan kolom.
- API kolom sudah memiliki mekanisme cadangan localStorage ketika backend
  tidak tersedia untuk beberapa operasi.
- Kolom bawaan menggunakan ID todo, in_progress, dan done. ID ini menentukan
  makna status, termasuk perhitungan task yang telah selesai.

3. PERUBAHAN YANG DIBUAT

A. Drag-and-drop kolom
Tombol panah serta baris "Urutan kolom" dihapus dari tampilan. Judul kolom
beserta ikon pegangan sekarang menjadi area yang dapat ditarik. Pengguna
menekan dan menahan area ini, menyeretnya ke kolom tujuan, lalu melepasnya.
Sisi sebelum atau sesudah titik tengah kolom tujuan menentukan posisi
sisipan. Kolom dapat dipindahkan beberapa posisi sekaligus dalam satu drag.
Pada papan desktop, arah sisipan mengikuti sisi kiri/kanan. Pada tampilan
sempit yang menyusun papan vertikal, arah sisipan mengikuti sisi atas/bawah.
Kolom yang ditarik menjadi lebih transparan. Garis ungu menunjukkan posisi
sisipan. Papan dapat bergulir horizontal ketika pointer mendekati tepinya.

B. Pengelolaan interaksi dan state
KanbanBoard menyimpan identitas kolom yang ditarik dan posisi tujuan.
App menerima ID kolom asal, ID tujuan, dan posisi before/after, kemudian
menyusun ulang array kolom dan menyimpannya dengan API yang sudah dibuat.
Tampilan diperbarui setelah penyimpanan berhasil. Jika urutannya sama,
tidak ada permintaan penyimpanan. Melepas drag di luar kolom membatalkan
pemindahan dan membersihkan indikator drag.
Selama penyimpanan berlangsung, drag kolom serta penambahan/penghapusan
kolom dinonaktifkan. Pengguna menerima notifikasi berhasil atau pesan error.
Drag kartu memakai identitas task, sedangkan drag kolom memakai tipe data
application/x-taskflow-column dan state tersendiri. Drop kartu ditangani
oleh kolom sebagai perubahan status task; drop kolom ditangani papan
sebagai perubahan urutan. Keduanya telah diuji agar tidak saling tertukar.

Sebagai akses keyboard, judul kolom dapat difokuskan dengan Tab. Tombol
panah kiri/atas dan kanan/bawah memindahkan kolom ke posisi sebelumnya atau
berikutnya. Ini tersedia melalui keyboard tanpa menampilkan tombol panah.

C. Penyimpanan melalui API
Ditambahkan metode reorder pada src/api/columns.js. Metode ini mengirim
PATCH /api/columns.php dengan payload column_ids yang berisi seluruh ID
kolom dalam urutan yang diinginkan. Nomor sort_order disusun dari 1.
Respons berhasil juga disimpan di localStorage sebagai cache kolom.

D. Backend PHP
Ditambahkan penanganan PATCH pada api/columns.php. Backend memeriksa bahwa
daftar ID berbentuk array berurutan, seluruh anggotanya string, tidak kosong,
tidak memiliki duplikat, dan cocok dengan semua kolom yang ada di database.
Daftar yang tidak valid ditolak dengan HTTP 422.
Pembaruan dilakukan dalam transaksi dengan penguncian baris kolom agar
perubahan sort_order diterapkan secara utuh. Transaksi dibatalkan jika
terjadi kesalahan database. API mengembalikan kolom dalam urutan terbaru.
Field sort_order sudah tersedia sehingga tidak diperlukan perubahan skema.

E. Penyimpanan lokal ketika backend tidak tersedia
Jika server tidak dapat dihubungi atau mengalami kesalahan 5xx, urutan
disimpan ke localStorage sesuai pola cadangan API kolom yang sudah ada.
Jika localStorage juga gagal menyimpan, aplikasi menampilkan kesalahan.
Penolakan 4xx dari server diteruskan sebagai kesalahan agar perubahan
yang ditolak tidak dianggap berhasil.

F. Tampilan dan dokumentasi
Gaya tombol panah diganti dengan kursor grab, transparansi kolom yang ditarik,
dan garis posisi sisipan. Ditambahkan petunjuk akses keyboard dan label
pada area judul. Footer sekarang mengarahkan pengguna untuk menarik judul. README diperbarui untuk menjelaskan
cara penggunaan, payload PATCH, dan batasan penyimpanan lokal.

G. Pengujian otomatis
Ditambahkan tests/column-order.spec.js untuk menguji urutan kolom,
persistensi, kolom utama, validasi API, mekanisme lokal pada viewport ponsel,
penanganan penolakan server, akses keyboard, pembatalan drag, dan pemindahan
kartu agar tidak mengubah urutan kolom.
Konfigurasi Playwright diubah menjadi satu worker dengan fullyParallel=false
karena tes integrasi mengubah papan database yang sama. Ini mencegah tes
penambahan kolom dan pengaturan urutan saling mengganggu.

4. CARA MENGGUNAKAN

1) Tambahkan kolom Masalah seperti biasa.
2) Tekan dan tahan judul/ikon pegangan kolom Masalah.
3) Tarik ke sisi kiri kolom Done atau sisi kanan kolom In Progress.
4) Pastikan garis ungu berada di lokasi sisipan yang diinginkan.
5) Lepaskan drag. Pada susunan tiga kolom utama, hasilnya menjadi:
   To Do -> In Progress -> Masalah -> Done.
6) Muat ulang halaman untuk melihat urutan yang telah tersimpan.
7) Untuk membatalkan, lepaskan drag di luar kolom.

7. BATASAN DAN PERILAKU PENTING

Urutan tampilan tidak mengubah ID atau status task. Task di done tetap
dihitung selesai meskipun kolom tersebut berpindah posisi. Tiga kolom utama
tetap wajib ada menurut perilaku aplikasi yang sudah tersedia.

Perubahan lokal ketika backend tidak tersedia belum disinkronkan otomatis
ke database. Saat backend kembali tersedia, pemuatan kolom menggunakan
urutan database. Pengguna dapat mengatur ulang urutan pada kondisi tersebut
untuk menyimpannya ke database. Aplikasi belum sepenuhnya dapat bekerja
offline karena API task masih memerlukan backend.

Pengaturan kolom menggunakan HTML Drag and Drop pada browser desktop.
Dukungan drag melalui layar sentuh mengikuti kemampuan browser; implementasi
ini belum menambahkan gesture sentuh khusus. Tes viewport 390 x 844 memakai
pointer mouse pada layout ponsel, sehingga tidak membuktikan drag sentuh
pada perangkat fisik. Akses keyboard tersedia melalui area judul kolom.
Pengerjaan ini tidak menambahkan pengaturan urutan kartu di dalam satu kolom.
