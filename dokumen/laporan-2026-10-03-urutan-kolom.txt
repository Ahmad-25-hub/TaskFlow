1. PERMINTAAN DAN TUJUAN
Pengguna meminta urutan kolom dapat diubah, misalnya kolom Masalah disisipkan
antara In Progress dan Done. Versi awal menggunakan tombol panah. Pengguna
kemudian meminta drag-and-drop seperti Trello, pembaruan laporan .txt ini,
serta push ke repository dan merge jika terjadi bentrok.
Tujuan akhir: kolom dapat dipindahkan langsung dengan drag, urutan tersimpan,
fungsi task tetap bekerja, dan perubahan terintegrasi dengan versi remote.

2. PERILAKU YANG TERSEDIA
- Tarik judul atau ikon pegangan kolom menuju kolom lain.
- Lepaskan sebelum/sesudah titik tengah kolom tujuan untuk memilih sisipan.
- Kolom dapat dipindahkan beberapa posisi sekaligus dalam satu drag.
- Garis ungu menunjukkan posisi sisipan, kolom asal tampil transparan.
- Papan dapat bergulir horizontal saat pointer mendekati tepi.
- Pada layout sempit/vertikal, posisi sisipan mengikuti arah atas/bawah.
- Lepaskan di luar kolom untuk membatalkan perpindahan.
- Keyboard: fokuskan judul dengan Tab, gunakan panah untuk mengatur urutan.
- Urutan disimpan setelah drop dan tetap tersedia setelah reload.
- ID todo, in_progress, done mempertahankan makna status walaupun berpindah.
- Kolom utama tetap tidak dapat dihapus.

3. IMPLEMENTASI
KanbanBoard mengelola ID kolom yang ditarik dan lokasi tujuan. Drag kolom
memakai tipe data application/x-taskflow-column. Drag kartu memakai ID task,
sehingga drop kolom dan drop kartu diproses sesuai jenis interaksinya.
KanbanColumn menyediakan area judul yang draggable dan akses keyboard.
WorkspaceBoard menyusun ulang array menggunakan ID asal, ID tujuan, dan
posisi before/after. Urutan yang sama tidak dikirim ulang. Selama proses
penyimpanan, interaksi perubahan kolom dikunci untuk mengurangi bentrokan.
Pesan keberhasilan/kesalahan disampaikan kepada pengguna.

Frontend menyimpan melalui:
PATCH /api/columns.php?workspace_id=<id>
Payload: { "column_ids": ["todo", "in_progress", "masalah", "done"] }
Daftar wajib memuat seluruh ID kolom workspace yang aktif, tanpa duplikat.
Backend memeriksa session dan keanggotaan, mengunci workspace dalam transaksi,
memvalidasi daftar ID, lalu memperbarui sort_order hanya pada workspace itu.
Papan workspace lain tidak ikut berubah. Respons mengembalikan urutan terbaru.
Jika penyimpanan gagal, urutan sebelumnya dipertahankan dan error ditampilkan.

4. MERGE DENGAN REMOTE
Perubahan lokal dibuat sebagai commit 7edfb47.
Fetch menemukan commit remote de12f6d yang menambahkan login dan multi-workspace.
Bentrok terjadi pada README.md, api/columns.php, playwright.config.js,
src/App.jsx, src/api/columns.js, dan src/components/KanbanBoard.jsx.

Penyelesaian dilakukan dengan mempertahankan struktur login/workspace remote,
lalu mengintegrasikan drag-and-drop ke WorkspaceBoard. State pending task dan
perubahan layout remote dipertahankan. API reorder diubah menjadi per-workspace,
dengan pemeriksaan akses yang sama seperti operasi kolom lainnya.

Versi remote mengganti penyimpanan lokal dengan backend berautentikasi.
Karena itu, versi gabungan menggunakan database dan tidak memakai fallback
localStorage dari implementasi awal. Backend harus aktif untuk menyimpan.
Tes lama kolom disesuaikan ke login/workspace dan dipindahkan ke
 tests/z-column-order.spec.js. Tes hasil merge menggunakan database sementara
 taskflow_test_* melalui npm test; database pengguna tidak dipakai untuk tes.
README dan laporan ini diperbarui mengikuti arsitektur hasil merge.

5. CARA MENGGUNAKAN
1) Login lalu buka workspace.
2) Tambahkan kolom Masalah.
3) Tekan dan tahan judul/ikon pegangan kolom Masalah.
4) Tarik ke kiri Done atau kanan In Progress.
5) Lepaskan ketika garis ungu berada pada posisi yang diinginkan.
6) Reload untuk memastikan urutan tetap tersimpan.

8. BATASAN
Drag menggunakan HTML Drag and Drop pada browser desktop. Dukungan sentuhan
mengikuti browser; belum ada gesture sentuh khusus. Tes viewport ponsel memakai
pointer mouse, sehingga tidak membuktikan drag sentuh pada perangkat fisik.
Pengerjaan ini tidak menambahkan pengaturan urutan kartu di dalam satu kolom.
